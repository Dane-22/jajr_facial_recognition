# Superadmin manual attendance: implementation plan

Status: **Implementation authorized and completed locally; production deployment pending**
Date: 2026-10-05

## Goal and agreed behavior

Add a **Manual Attendance** page in the admin portal where a Superadmin can record an individual employee's time-in or time-out when the normal camera/geofence flow was missed. A single time-in or time-out creates one `attendance_logs` record and maintains the same open-session state used by scanner attendance. A historical paired correction creates two distinct records, one `IN` and one `OUT`, in one atomic operation. No flow may silently edit, delete, or merge existing records.

Initial-version rules:

- Select one employee, then show their assigned sites, current open time-in (if any), and recent attendance records before an action is available.
- **Single time in:** require no open session; select one active site assigned to that employee.
- **Time out:** require an open session; use that session's site automatically and require the chosen time to be after its time-in. An unmatched time-out needs a separate correction workflow if it is desired.
- Enter explicit attendance date/time in `Asia/Manila`; default to the current time. Allow entries up to **30 days back** and reject future times. The 30-day limit may be configurable, but 30 days is the initial setting.
- Reject a **single** backdated entry if it conflicts with an open session or later attendance. When a missed shift has later attendance, offer a **paired correction** on this page: enter both time-in and time-out, require `IN < OUT`, use one assigned site and a reason, and verify that the interval does not overlap or reorder any existing attendance. Insert the two separate records together. A paired historical correction must not create or close the employee's current open session.
- Allow a backdated time-out for an existing open session only if it follows that session's time-in and does not conflict with subsequent records.
- Require a written reason (proposed 10–500 characters). Show a confirmation summary with employee, action, site, effective time, and reason. Disable repeat submission while saving.
- Identify the event clearly as **Manual** in attendance and audit views. Store the Superadmin actor, reason, **effective attendance time**, and **actual creation time** so they remain recoverable from the attendance record, not only from a separate UI message. Show both times in manual-entry details. Preserve existing location fields as absent for a manual entry; do not invent coordinates.
- Use `Asia/Manila` consistently in the form, confirmation, attendance views, and exports. Convert explicitly at the API/database boundary and store the effective time as an unambiguous instant using the existing database timestamp convention.

## Current code to build on

- `frontend/src/components/AdminLayout.jsx` owns the admin navigation and rendered tab content. The new tab belongs here, visible only to Superadmin.
- `frontend/src/components/SiteManagement.jsx` already exposes a Superadmin time-out correction form under Settings. It calls `POST /api/admin/time-out-corrections/:userId`.
- `backend/controllers/siteController.js` implements that correction. It checks the current `admins.position` in the database, locks the employee row, inserts an `OUT` log, deletes the open session, and writes an audit record in one transaction. The new page should share or consolidate this operation so two manual time-out paths do not drift.
- `backend/controllers/attendanceController.js` handles scanner attendance. It locks the employee row, validates site/session state, inserts a log, updates `employee_site_sessions`, and broadcasts `attendance:new`. New manual writes must use compatible locking and session transitions.
- `backend/utils/siteMigration.js` defines `employee_sites` and `employee_site_sessions`. `attendance_logs` contains status, timestamp, nullable coordinates, and site ID. Existing reports read `attendance_logs`, so valid manual records should flow into reports and exports; their source should still be identifiable.
- `backend/middleware/authMiddleware.js` verifies an admin JWT but does not itself enforce Superadmin. A dedicated database-backed Superadmin check is needed on **every new read and write endpoint**. Hiding the navigation item is only a UI convenience.

## Implementation sequence after the go signal

1. **Lock the time contract.** Set the maximum age for manual entries to 30 days, with an explicit configuration point for a later policy change. Use `Asia/Manila` for input and display and explicit conversion to/from the database's timestamp convention. Confirm the conversion against the production MySQL session timezone before writes are enabled; avoid relying on browser or server local timezone defaults.
2. **Data provenance.** Add an idempotent migration for manual-entry metadata tied to each `attendance_logs.id` (for example, source, acting admin ID, reason, and actual creation time). Keep existing scanner rows and queries valid. Record matching `audit_logs` events such as `MANUAL_TIME_IN` and `MANUAL_TIME_OUT`, including effective time, creation time, actor, employee, site, reason, and log/session IDs. Link the two distinct records of a paired correction with a shared operation ID. Preserve the existing correction's audit coverage when consolidating the flow.
3. **Protected API.** Add a Superadmin-only employee/context read endpoint and write operations for single entries and paired historical corrections. Recheck the admin's live database position at request time. Validate employee ID, status, exact timestamp and timezone, site assignment, reason, 30-day limit, and permitted chronology server-side. Return an actionable `409` if a single entry conflicts with later attendance, suggesting the paired correction when applicable. Return specific `400`, `403`, `404`, and `409` errors.
4. **Atomic attendance service.** Use the same per-employee lock as scanner attendance. For a single entry, check later records and the open session, insert the manual log and provenance/audit record, then create or close `employee_site_sessions`. A backdated `OUT` is valid only after the open `IN` and before any subsequent record. For a paired correction, validate both times and the surrounding attendance sequence, then insert two distinct logs and their provenance/audit records in one transaction without changing a current open session. On any failure, roll back all changes. Emit `attendance:new` only after commit, using each chosen effective attendance timestamp. Prevent double clicks and concurrent scanner/manual requests from producing duplicate or conflicting state. Reuse this service for the existing time-out correction so its Superadmin authorization, validation, and audit behavior are preserved.
5. **Page and navigation.** Add a Superadmin-only Manual Attendance tab. Use searchable employee selection and show each employee as **one mobile card per employee**, with their name prominent and the open-session state clearly labeled. Put that employee's single time-in, single time-out, and paired correction controls, assigned site, Asia/Manila date/time fields, reason, confirmation, and feedback inside their card or accessible expanded sections. Show recent attendance as separate, clearly labeled records within the selected employee's details; never merge separate attendance records. Show both effective attendance time and actual creation time for manual records. Keep the employee cards compact and readable, with no page-level horizontal overflow or mobile data table. At wider widths, use a layout that remains easy to scan. Validate at 320, 360, 390, and 430 px, short screens, and 200% browser zoom; keep actions reachable above the floating chat control. Restrict direct access as well as navigation.
6. **Replace existing correction UI.** Remove the time-out correction form from Settings and put a shortcut to the new Manual Attendance page in its place. Preserve the correction's behavior through the shared backend service, including Superadmin authorization, validation, and audit logging. Avoid maintaining two separate validation rules and audit formats.
7. **Attendance views and exports.** Display effective timestamps in Asia/Manila wherever manual attendance appears. In manual-entry details and relevant exports, also include the actual creation time, source, actor, and reason without changing existing record counts or merging events.
8. **Verification.** Test anonymous/Admin/Superadmin access (including demotion after token issue); time-in/time-out and repeated/overlapping attempts; assigned/inactive sites; missing sessions; backdated/future/out-of-order times; exactly-at and beyond the 30-day boundary; historical pairs before later records and pairs that overlap existing records or an open session; paired-transaction rollback and audit linkage; timezone conversion and export display; scanner concurrency; and report/export visibility. Manually review keyboard access and desktop layout, and capture mobile screenshots showing one card per employee at the target widths and 200% zoom. No production deployment without a later explicit request.

## Confirmed decisions

On 2026-10-05, the Superadmin chose the recommended policy, superseding the earlier draft: allow entries up to 30 days back; reject conflicting single entries; provide paired time-in/time-out correction for a missed historical shift when later attendance exists; require an open time-in for a single manual time-out; require an assigned site and written reason; use Asia/Manila for input and display while storing exact instants; show both effective and creation times for manual entries; and replace the Settings correction form with a shortcut to the new page.
